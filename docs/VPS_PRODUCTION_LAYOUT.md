# VPS Production Directory Layout

**Status: DESIGN + PROVISIONING SCRIPT ONLY. Nothing has been deployed.** Part 2 of the VPS Production Deployment block (2026-09-24). Adapts `docs/VPS_DEPLOYMENT_PREP.md`'s single flat `/opt/nhl_engine/` layout into one that actually separates code from mutable state, per that block's explicit instruction not to store mutable production databases inside a disposable deploy path.

## The real constraint

Every database/log/archive path in this codebase is resolved as `Path(__file__).resolve().parent... / "something.db"` -- relative to wherever the code is checked out (`REPO_ROOT`), by design, matching today's exact local-Mac setup. That is correct and is **not being redesigned** here (Part 1: reuse, don't rebuild). But it means a naive "the app directory IS the data directory" deploy (a fresh `git clone`/`rsync` replacing the whole tree) would delete real, non-regenerable production data the moment someone redeploys code.

## The fix: symlinks, not a rewrite

Physical mutable state lives outside the code checkout. The checkout gets symlinks at the exact paths the code already expects, pointing back into the persistent directories. **Zero lines of application code change.** A deploy becomes `git pull` (or a fresh checkout + re-run the provisioning script) in `app/` only -- `data/`, `backups/`, `logs/`, `secrets/` are never touched by a deploy.

```
/opt/nhl-engine/
├── app/                                  # git checkout -- disposable, redeployable, no state
│   ├── .venv/
│   ├── nhl.db                            -> symlink -> ../data/nhl.db
│   ├── .env                              -> symlink -> ../secrets/.env
│   ├── operational/
│   │   ├── paper_bankroll.db             -> symlink -> ../../data/operational/paper_bankroll.db
│   │   ├── auth_store.db                 -> symlink -> ../../data/operational/auth_store.db
│   │   ├── prospective_observations.db   -> symlink -> ../../data/operational/prospective_observations.db
│   │   ├── special_teams_history.db      -> symlink -> ../../data/operational/special_teams_history.db
│   │   ├── odds_archive/                 -> symlink -> ../../data/operational/odds_archive/
│   │   ├── backups/                      -> symlink -> ../../backups/
│   │   └── logs/                         -> symlink -> ../../logs/
│   ├── fantasy/storage/
│   │   ├── fantasy_store.db              -> symlink -> ../../../data/fantasy/storage/fantasy_store.db
│   │   └── yahoo_token.enc               -> symlink -> ../../../data/fantasy/storage/yahoo_token.enc
│   └── research/
│       ├── real_nhl_pbp/research_pbp.db          -> symlink -> ../../../data/research/real_nhl_pbp/research_pbp.db
│       └── moneypuck_ingestion/research_moneypuck.db -> symlink -> ../../../data/research/moneypuck_ingestion/research_moneypuck.db
├── data/                                 # PERSISTENT -- survives every deploy, every re-clone
│   ├── nhl.db
│   ├── operational/{paper_bankroll,auth_store,prospective_observations,special_teams_history}.db
│   ├── operational/odds_archive/live/
│   ├── fantasy/storage/{fantasy_store.db, yahoo_token.enc}
│   └── research/{real_nhl_pbp,moneypuck_ingestion}/*.db
├── logs/                                 # journalctl is primary (Part 15); this is a fallback for any file-based logs
├── backups/                              # operational/backup_databases.py output (rotated, 14-deep) + odds archive tarballs
└── secrets/
    └── .env                              # chmod 600, owner-only -- see docs/VPS_SECRETS_MANAGEMENT.md
```

## Provisioning

`deploy/provision_layout.sh` (new, this block) creates the five top-level directories and every symlink above, idempotently (safe to re-run). It never overwrites an existing real file with a symlink -- if a target path already has real data (e.g. a first deploy that hasn't been separated yet), it moves the real file into `data/` first, then symlinks, so no existing history is lost. See that script's own comments for the exact sequence.

## What this does NOT change

- No code in `operational/`, `research/`, `dashboard/`, `fantasy/`, or `db.py` changes. Every module keeps resolving `REPO_ROOT`-relative paths exactly as it does today; the symlinks make those paths physically point outside `app/`.
- `research/real_nhl_pbp/research_pbp.db` and `research/moneypuck_ingestion/research_moneypuck.db` are REPRODUCIBLE/OPTIONAL per `docs/BACKUP_AND_RESTORE.md`'s own classification -- included in the layout for consistency, not because losing them during a bad deploy would be catastrophic.
- `*_cache.json` files (ingestion health, data readiness, odds/moneyline/sweep caches) are deliberately **not** symlinked -- they're temporary, regenerated by the next real run, never backed up (per `docs/BACKUP_AND_RESTORE.md`), and there is no harm in a fresh one appearing in a fresh `app/` checkout.
